# AI/AX Learning Lab

작은 업무 요구에 맞는 구성을 AI와 설계·구현하고 실제 결과를 판단하는 학습 저장소입니다. [CURRENT_WEEK.md](CURRENT_WEEK.md)에서 현재 주차로 이동하세요. 전체 순서와 공통 안내는 [LEARNING_GUIDE.md](LEARNING_GUIDE.md)에 있습니다.

코드 실습은 Java와 Gradle Wrapper를 사용합니다. 개념과 선택 이유는 언어에 독립적으로 설명하고 코드로 근거를 확인합니다.

초안·코드·기준 문장은 AI의 도움으로 만들어도 됩니다. 학습자는 목적·범위·기대 결과를 검토하고 실제 결과의 수용 여부를 판단합니다. 모든 주차에서 **필요한 개념 이해 → 도구 사용 → 결과와 구조 확인 → 수정·재사용**을 이어갑니다. 도구의 정의·역할과 파일·코드·설정의 구조 확인은 기본 학습에 포함합니다.

제작 활동에서는 자기 요구의 입력·결과·실패 처리를 선택하고 기존 도구·SDK·예제로 구현해 실제로 사용합니다. 3주차는 자기 MCP 기능을 만들고, 6~7주차는 선택한 한 방식에서 자기 도구를 모델에 연결합니다. 구현과 설계안은 AI에 맡길 수 있으며, 학습자는 선택 이유와 실제 동작을 확인합니다.

포트폴리오가 있으면 그 프로젝트의 요구와 기존 스택에 적용합니다. 해당 기술이 앱에 필요하지 않으면 제공 과제로 필수 역량을 확인하고 앱에는 억지로 추가하지 않습니다. 개인 프로젝트가 없어도 주차의 제공 업무·자료로 진행할 수 있습니다. Skill Creator·SDK·프레임워크·AI로 만든 결과에 후속 요구를 적용하면서 무엇을 바꾸고 유지할지 판단합니다. 설계 문서를 혼자 먼저 작성할 필요는 없습니다.

실제 모델 AI 앱이 표준 완료 경로입니다. 기본 과제는 6~7주차 주문 Tool과 8주차 환불 정책 RAG를 10주차 문의 도우미로 연결하고, 11~12주차 **질문→필요한 조회·검색·실제 모델→API 또는 화면의 결과**로 사용·확장합니다. 사람이 자료를 옮기지 않아도 동작해야 합니다. MCP 최소 쓰기, 상태·조건 분기, 실제 임베딩·저장소 연결과 문서 추가·개정·제외는 필수입니다. 영구 저장 후 재개·복잡한 동시성·고급 검색·공개 운영은 심화입니다. AX 결과만으로 AI 앱 통합을 완료했다고 판단하지 않습니다.

구조를 볼 때는 작동한 예제에서 입력부터 결과까지 따라가고 왜 구성을 나눴는지, 원하는 동작을 바꾸려면 어디를 고칠지 살펴봅니다. 분석은 실제 원문 근거와 자신의 해석을 주차 노트에 남기고, 작은 변경의 예상과 결과를 비교합니다. 코드·설정·실행 결과는 위치를 연결하며 같은 내용을 여러 양식에 반복하지 않습니다.

각 주차의 해설은 실제 문장·코드·입출력을 짚고, 그 차이의 의미와 판단의 한계를 설명합니다. 기본 개념을 읽고 도구를 사용한 뒤 자신의 결과와 대조하세요. Day별 안내의 행동·남길 결과·완료 확인에 따라 진행하며 분석 노트 초안에도 AI의 도움을 받을 수 있습니다.

중요한 새 구성에서는 **요구와 추천 구성의 해설 → 학습자의 짧은 검토 → 구현·실행 → 결과 해석**을 이어갑니다. AI가 실제 코드·입력으로 추천 이유와 예상 동작을 설명하면, 예상이나 수용·수정 의견을 짧게 말하고 구현으로 이어갑니다. 이미 정한 구성의 단순 수정에는 이 대화를 반복하지 않습니다. 실행 후에는 그 결과를 만든 원리와 다음 요구에서 선택을 바꿀 조건을 함께 살펴봅니다. 실제 동작 확인과 이해를 구분하며 12단계·Day 1~5의 소요 시간은 유연하게 둡니다.

## 파일과 폴더

| 위치 | 들어 있는 내용과 사용할 때 |
|---|---|
| `CURRENT_WEEK.md` | 현재 주차와 작업 폴더로 이동하는 짧은 안내 |
| `LEARNING_GUIDE.md` | 전체 주차의 본문과 공통 안내를 한 번에 읽는 문서 |
| `AGENTS.md` | AI와 협업할 때 적용할 공통 지침 |
| 시작한 주차의 `README.md` | 개념 설명, Day별 실습, 복사할 요청문과 완료 확인. 시작 전 주차의 본문은 전체 가이드에서 미리 확인 |
| 주차의 실제 프로젝트 | `ticket-title-normalizer/`, `rag_lab/`처럼 실행·수정할 코드와 설정. 주차 README가 주요 파일을 소개 |
| 주차의 학습 기록 파일 | 분석·실행 결과·수정 이유. 지정된 파일이나 기존 노트를 사용 |
| 필요한 주차의 `examples/` | 실제 파일 구성을 읽고 비교할 예제 |
| `.learning/` | `state.json`에 현재 주차와 배포 자료를 저장. 동기화 도구가 관리하며 평소 편집할 필요 없음 |
| `.local/` | 개인·임시 자료와 보존 사본. Git 제외 |

별도 측정기·채점표·전체 대화 로그는 만들지 않습니다. 기록 위치의 지정이 없으면 주차의 `notes.md` 또는 기존 노트를 사용합니다. 실제 코드와 테스트는 위치를 연결하며 같은 기록을 여러 파일에 반복하지 않습니다. 현재 Day에 필요한 확인을 못 했다면 그 항목과 이유를 남깁니다. 이후 Day나 선택하지 않은 기능을 현재 과제의 미완료 사유로 추가하지 않습니다.

## 기존 학습을 이어갈 때

진도는 실제로 실행·이해·확인한 내용으로 판단합니다. 각 주차의 기초 설명과 Day 1부터 읽고 해당 활동의 결과가 있을 때만 건너뜁니다. 이미 쓴 초안을 버릴 필요는 없습니다.

개정된 필수 활동은 기존 코드·설정·실행 근거를 보고 필요한 부분만 보충합니다. 2~4주차 실습을 마쳤다면 각 주차의 **기존 학습자 보충 안내**를 2→3→4 순서로 읽어 현재 Skill·Tool·통합 결과의 원리와 선택 이유를 다시 살펴볼 수 있습니다. 기존 실행의 반복이나 노트·블로그 재작성은 요구하지 않습니다. 현재 주차를 되돌리거나 기존 기록을 취소하지 않으며, 문서 갱신으로 보충 학습까지 완료한 것으로 바꾸지 않습니다.

오프라인으로 먼저 진행해도 실제 모델·Host 연결을 확인하는 활동은 별도로 남습니다. 다음 주차로 이동하거나 개인 프로젝트를 완성했다고 미확인 연결이나 제작을 완료한 것으로 바꾸지 않습니다. 6~7주차의 공통 제작은 선택한 한 방식에서 확인하면 되며 두 방식으로 반복할 필요는 없습니다.

`CURRENT_WEEK.md`, 전체 가이드, 루트·주차 README는 과정 관리 대상입니다. `sync`는 학습자가 만든 프로젝트·Skill·기록과 `AGENTS.md`를 덮어쓰지 않습니다. 프로젝트 내부 README도 학습자 파일입니다. 개정 예제가 필요하면 새 임시 학습 저장소와 비교해 필요한 파일만 반영합니다. 다음 주차는 시작할 때 최신 자료를 받습니다.

폴더 구조를 바꾸어 이어가는 경우 기존 기록은 내용 그대로 보존합니다. 이전 실험 묶음은 해당 주차의 `records/`에 있을 수 있습니다. 이전·새 경로는 `.local/folder-migration/moves.json`, 더 이상 쓰지 않는 자료의 수정본은 `.local/previous-course-materials/`에서 확인할 수 있습니다.

## Git과 외부 공유

검증한 의미 있는 변경에 `type(scope): 한국어 제목` 형식으로 커밋합니다. 매일 커밋하거나 빈 커밋을 만들 필요는 없습니다. 토큰·비밀값·개인 자료는 올리지 않습니다. 공개·배포는 선택이며 대상과 범위를 확인한 뒤 결정합니다.

이 저장소만 clone한 경우 과정 관리 명령을 실행할 필요는 없습니다. 이미 제공된 주차 안내로 학습하고 새 자료가 반영되면 업데이트합니다.
