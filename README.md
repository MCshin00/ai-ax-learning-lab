# AI/AX Learning Lab

요구에서 필요한 구성을 도출하고 AI와 설계·구현한 뒤 실제 결과를 판단하는 학습 저장소입니다. [CURRENT_WEEK.md](CURRENT_WEEK.md)에서 현재 주차 README로 이동하세요. 전체 본문과 공통 안내는 [LEARNING_GUIDE.md](LEARNING_GUIDE.md)에 있습니다.

1~10주차는 제공 업무·자료만으로 기술의 구성과 연결을 배웁니다. 개인 프로젝트나 다른 프로젝트 적용 과제를 요구하지 않습니다. 11~12주차는 학습자가 원하는 포트폴리오의 목적·범위·스택·형태·배포 여부를 정하고 제작하도록 돕습니다. 기존 프로젝트가 없어도 진행할 수 있습니다.

**개념 이해 → 요구에서 구성 도출 → AI와 설계·구현 → 실행 결과 해석**으로 진행합니다. 교재가 실제 코드·입출력과 설계 이유를 설명하고, AI는 구성과 구현을 돕습니다. 학습자는 추천의 이유와 예상 동작을 검토하고 실제 결과와 대조합니다. 새로운 선택이 없는 단순 수정에는 같은 설계 대화를 반복하지 않습니다.

제작에서는 공개할 기능·계약·상태·실행 정책부터 도출합니다. 참고 코드의 구조는 선택의 근거를 읽을 자료이며 학습자의 고정 답안이 아닙니다. SDK와 업무 함수는 재사용하고, 선택한 구성을 실제로 실행할 진입점까지 AI와 만듭니다. 하네스 v1에서 기본 엔진의 전체 흐름을 설계하고 v2에서 비교에 근거한 개선을 합니다.

Java가 기본이며 실제 LangChain·LangGraph 비교와 Dify Tool Plugin에 필요한 부분만 Python을 사용합니다. 개념은 입력·출력·책임·상태·실패·선택 이유를 중심으로 설명하고 언어 문법은 코드 이해에 필요한 만큼 다룹니다.

파일 편집·변경 확인·빌드·테스트·일반 실행과 앱 설정은 IDE나 앱 화면에서 진행합니다. CLI는 필요한 기능이거나 자동화·프로세스 연결·반복 실행에 더 적합할 때 사용합니다. 각 실습의 터미널 예시는 해당 실행 방법을 선택했을 때의 안내이며, 같은 작업을 UI와 CLI로 반복할 필요는 없습니다.

평가·비교가 주제인 활동은 작은 제공 사례와 필요한 결과로 수행합니다. M1~M5는 같은 과제를 각 방식으로 한 번씩 수행하는 것이 기본입니다. 대량 반복·통계 순위·별도 측정기·학습자 점수표·전체 대화 수집을 요구하지 않습니다. 코드·설정·실행 결과도 산출물이며 중요한 해석은 기존 주차 노트에 누적합니다.

## 파일과 폴더

| 위치 | 들어 있는 내용과 사용할 때 |
|---|---|
| `CURRENT_WEEK.md` | 현재 주차와 작업 폴더로 이동하는 짧은 안내 |
| `LEARNING_GUIDE.md` | 전체 주차의 본문과 공통 안내를 한 번에 읽는 문서 |
| `AGENTS.md` | AI와 협업할 때 적용할 공통 지침 |
| 시작한 주차의 `README.md` | 개념 설명, Day별 실습, 복사할 요청문과 완료 확인. 시작 전 주차의 본문은 전체 가이드에서 미리 확인 |
| 주차의 실제 프로젝트 | `ticket-title-normalizer/`, `rag_lab/`처럼 실행·수정할 코드와 설정. 주차 README가 주요 파일을 소개 |
| 주차의 학습 기록 파일 | 분석·실행 결과·수정 이유. 지정된 파일이나 기존 노트를 사용 |
| 필요한 주차의 `examples/` | 실제 파일 구성을 읽고 비교할 예제 |
| `.learning/` | `state.json`에 현재 주차와 배포 자료를 저장. 동기화 도구가 관리하며 평소 편집할 필요 없음 |
| `.local/` | 개인·임시 자료와 보존 사본. Git 제외 |

별도 측정기·채점표·전체 대화 로그는 만들지 않습니다. 기록 위치의 지정이 없으면 주차의 `notes.md` 또는 기존 노트를 사용합니다. 실제 코드와 테스트는 위치를 연결하며 같은 기록을 여러 파일에 반복하지 않습니다. 현재 Day에 필요한 확인을 못 했다면 그 항목과 이유를 남깁니다. 이후 Day나 선택하지 않은 기능을 현재 과제의 미완료 사유로 추가하지 않습니다.

## 학습 진행

진도는 실제로 실행·이해·확인한 내용으로 판단합니다. 각 주차의 기초 설명과 Day별 안내를 순서대로 읽고, 해당 활동을 이미 수행했다면 코드·설정·실행 결과와 기록을 활용합니다.

오프라인으로 먼저 진행해도 실제 모델·Host 연결을 확인하는 활동은 별도로 남습니다. 다음 주차로 이동하거나 개인 프로젝트를 완성했다고 미확인 연결이나 제작을 완료한 것으로 바꾸지 않습니다. 6주차는 Tool 계약과 호출 앱의 설계, 7주차는 같은 업무의 세 방식 비교와 상태·분기의 설계를 각각 다룹니다.

`CURRENT_WEEK.md`, 전체 가이드, 루트·주차 README는 과정 관리 대상입니다. `sync`는 학습자가 만든 프로젝트·Skill·기록과 `AGENTS.md`를 덮어쓰지 않습니다. 프로젝트 내부 README도 학습자 파일입니다. 다음 주차의 자료는 주차를 시작할 때 받습니다.

## Git과 외부 공유

검증한 의미 있는 변경에 `type(scope): 한국어 제목` 형식으로 커밋합니다. 매일 커밋하거나 빈 커밋을 만들 필요는 없습니다. 토큰·비밀값·개인 자료는 올리지 않습니다. 공개·배포는 선택이며 대상과 범위를 확인한 뒤 결정합니다.

이 저장소만 clone한 경우 과정 관리 명령을 실행할 필요는 없습니다. 이미 제공된 주차 안내로 학습하고 새 자료가 반영되면 업데이트합니다.
