# 작은 Skill의 구성을 따라가기

생성한 Skill이 `SKILL.md` 하나로 충분하다면 그 구성을 그대로 사용합니다. 이 예제는 템플릿과 참고 자료를 나눴을 때의 역할을 함께 보기 위한 비교 자료입니다. 같은 구조를 직접 재현할 필요는 없습니다.

```text
issue-brief-example/
├── SKILL.md
├── assets/issue-template.md
└── references/writing-rules.md
```

`lab/practice/`는 학습 자료 위치입니다. 이 예제가 여기에 있다고 `$issue-brief-example` 이름으로 호출되거나 자동 선택되는 것은 아닙니다. 아래 요청처럼 파일 경로를 지정하면 자료를 읽고 결과를 확인할 수 있습니다. Skill의 등록·선택 확인은 주차 README의 실제 제작 실습에서 진행합니다.

## 입력에서 출력까지

주차 README와 같이 `week02-codex-skills/lab/`을 작업 위치로 열고 다음 요청을 사용합니다. 저장소 루트에서 진행한다면 경로 앞에 `week02-codex-skills/lab/`을 붙입니다.

> `practice/skill-example/issue-brief-example/SKILL.md`를 읽고 필요한 부속 파일도 확인해 아래 제보를 이슈 초안으로 정리해 주세요. 결과는 채팅에 보여 주세요.
>
> Android 앱에서 로그인 버튼을 누르면 로딩이 계속됩니다. 어제까지는 됐고 앱을 다시 켜도 같습니다. 웹에서는 로그인됩니다.

가능한 결과는 다음과 같습니다. 문구 일치가 목표는 아닙니다.

```markdown
# Android 앱 로그인 버튼을 누른 뒤 로딩이 끝나지 않음

## 증상
- 로그인 버튼을 누르면 로딩이 계속된다.
- 제보에 따르면 어제까지는 로그인할 수 있었다.
- 웹에서는 로그인된다.

## 재현 정보
- Android 앱에서 로그인 버튼을 누름.
- 앱을 다시 켜도 같은 증상이 나타남.

## 환경
- Android 앱. 기기, 운영체제 버전, 앱 버전은 미확인.

## 확인할 질문
- 사용 중인 앱 버전과 Android 버전은 무엇인가요?
```

## 실제 파일과 대조하기

- [SKILL.md](issue-brief-example/SKILL.md)의 `description`은 어떤 요청에 쓰는지 알립니다. 본문은 할 일과 부속 자료를 읽을 시점을 연결합니다. 둘의 역할을 비교해 봅니다.
- [작성 규칙](issue-brief-example/references/writing-rules.md)은 출력 양식이 아닙니다. 이 입력에서는 환경 정보의 누락과 “어제” 처리를 판단하는 데 쓰입니다. 정보가 충분하고 날짜 문제가 없을 때도 이 파일을 읽어야 하는지 본문의 읽기 조건과 대조합니다.
- [템플릿](issue-brief-example/assets/issue-template.md)은 결과의 항목과 순서를 제공합니다. 출력에서 어느 부분이 이 파일을 따랐는지 찾습니다.

AI에게 세 파일 사이의 연결과 나눈 이유를 설명받고, 설명이 실제 내용과 맞는지 살펴봅니다. 이 정도 분량은 한 파일로 합쳐도 동작할 수 있습니다. 분리하면 형식과 특수한 작성 규칙을 따로 고치기 편하지만, 읽을 파일이 늘어납니다. 모든 Skill에 폴더 세 개나 스크립트가 필요한 것은 아닙니다.

이해를 확인하려면 원하는 변화 하나를 고릅니다. 예를 들어 **환경을 먼저 보이게 하려면 어느 파일을 바꿀지**, **정확한 제보 날짜가 있는 새 입력은 어떻게 처리할지** 예상해 봅니다. 자기 실습용 복사본을 수정하거나 새 입력으로 확인하고 예상과 결과를 비교합니다. 별도 분석 보고서는 필요하지 않습니다.
