# 버그 제보 정리

제공된 사실을 유지하며 개발 담당자가 읽을 수 있는 짧은 이슈 초안을 작성한다. 입력에 없는 원인이나 환경을 만들어 내지 않는다.

## 작성 방법

- 증상, 사용자가 실제로 한 행동, 제공된 환경을 구분한다.
- 정보가 빠졌거나 서로 맞지 않으면 [작성 규칙](references/writing-rules.md)을 읽어 미확인 내용을 처리한다. 날짜가 상대 표현으로 주어진 경우에도 해당 규칙을 확인한다.
- [이슈 템플릿](assets/issue-template.md)의 항목에 내용을 채운다. 기본 출력은 채팅의 Markdown 초안이며, 사용자가 파일 출력을 요청한 경우 지정한 위치에 저장한다.
- 완성한 초안을 입력과 대조한다. 원인을 단정하지 않았는지, 사용자가 이미 제공한 정보를 다시 묻지 않았는지 확인한다.
