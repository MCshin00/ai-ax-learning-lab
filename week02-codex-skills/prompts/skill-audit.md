# 사용한 Skill의 구조와 설계 이유 살펴보기

Skill을 한 번 사용한 뒤 `week02-codex-skills/lab/`에서 아래 요청을 직접 보냅니다. 혼자 분석표를 먼저 제출할 필요는 없습니다.

주차 README Day 2의 해설에서 선택과 수행 지침, 제보가 참고 규칙·템플릿을 거치는 흐름, 파일 분리의 효과와 한계를 먼저 읽습니다. 교재의 설명을 자신의 Skill에 적용하고 다른 점을 이해하는 데 아래 요청을 사용합니다. 기존 분석 글이나 대화로 이 관계를 이미 이해했다면 같은 분석을 반복할 필요는 없습니다.

구성 차이를 비교하려면 `practice/skill-example/study-example.md` 또는 이미 설치한 작은 Skill을 함께 엽니다. 비교 자료를 쓰기 위해 또 다른 Skill을 완성할 필요는 없습니다.

```text
방금 사용한 Skill의 실제 폴더와 SKILL.md를 읽어 구조를 설명해 주세요.
YAML 메타데이터의 name·description, 그 아래 수행 지침을 실제 위치와 함께 짚어 주세요.
부속 파일이 있으면 각각 언제 읽거나 실행하는지 알려 주세요. 없는 파일을 만들지는 마세요.
방금 요청이 어떤 지침과 자료를 거쳐 결과로 이어졌는지 필요한 경로를 따라가 주세요.
본문·참고 자료·템플릿·스크립트를 나눈 이유와 현재 효과를 설명해 주세요.
교재의 제보 예시와 다른 구조라면 그 차이가 실제 작업에 어떤 영향을 주는지 풀어 주세요.
자료로 확인한 이유와 추정한 이유를 구분해 주세요.
지침, 재사용 템플릿이 있다면 그 형식, 이번 출력 내용을 구분해 주세요.
원하는 출력 형식이나 동작을 바꿀 때 수정할 위치와 예상 결과를 짚어 주세요.
작은 예제는 전체 구성을 읽어도 됩니다. 관련 없는 라이브러리 내부까지 분석할 필요는 없습니다.
아직 파일을 고치지는 마세요.
```

설명받은 위치를 실제 파일에서 찾고 자신의 요청·출력과 대조합니다. Day 4에서 바꿔 볼 조건과 예상 결과를 정합니다. 문제가 없으면 출력 항목 순서처럼 유용한 작은 변경을 골라도 됩니다.
