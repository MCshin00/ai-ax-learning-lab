# Issue Summary

제공된 버그 제보를 한 줄의 이슈 제목과 아래 네 항목으로 간결하게 정리한다. 단일 제보는 기존 형식 그대로 처리하고, 여러 제보는 공통 사실을 묶되 각 사실의 출처와 차이를 남긴다.

## 정리 원칙

- 입력에 있는 사실만 사용한다. 원인, 환경·버전, 재현 단계, 기대 동작을 추측하거나 외부 지식으로 채우지 않는다.
- 제보자의 추정은 추정으로 표시한다. 불확실한 표현, 발생 빈도, 오류 메시지를 보존하고 모순된 내용은 임의로 확정하지 않는다.
- 재현 순서는 입력에 명시된 행동과 순서만 번호 목록으로 적는다. 순서가 불명확하면 알려진 행동만 나열하고 순서 확인이 필요하다고 표시한다. 누락된 준비 단계나 중간 행동을 추가하지 않는다.
- 증상·재현 순서·기대 동작 중 제공되지 않은 항목은 `입력에 없음`으로 표시한다. 정보가 부족해도 우선 정리 결과를 제공한다.
- 빠지거나 모호한 정보 중 이슈를 이해하고 재현하는 데 필요한 내용만 마지막 항목에서 짧은 질문으로 묻는다. 이미 제공된 정보를 다시 묻지 않는다. 필요한 질문이 없으면 `없음`으로 표시한다.

## 여러 제보를 함께 정리할 때

- 입력의 제보 ID를 그대로 사용한다. ID가 없으면 입력 순서로 임시 번호를 붙이고 출처를 구분하기 위한 번호임을 밝힌다. 단일 제보에는 ID나 추가 제보를 요구하지 않는다.
- 대상·플랫폼과 명시된 발생 조건·증상·후속 관찰이 맞는 공통 사실만 묶어 반복을 줄인다. 공통 문장 옆에 해당 사실을 뒷받침하는 모든 제보 ID를 붙인다. 일부 제보에만 있는 행동·조건은 그 출처만 붙여 별도로 남긴다. 비슷한 증상만으로 같은 원인이나 같은 재현 조건이라고 확정하지 않는다.
- 플랫폼·조건·관찰 결과가 다르면 같은 항목 안의 별도 줄이나 표로 구별한다. 실패 후 성공한 관찰도 보존하며, 다른 제보가 틀렸다는 근거로 쓰지 않는다. 서로 맞지 않는 내용은 양쪽 출처와 함께 남기고, 실제 상충인지 조건 차이인지는 확인 질문으로 돌린다.
- 재현 행동은 제보별 또는 공통 근거가 있는 묶음별로 적는다. 서로 다른 제보의 행동을 하나의 연속된 재현 순서로 이어 붙이지 않는다.
- 빠진 환경·버전·원인과 모호한 증상은 다른 제보의 값으로 채우지 않는다. 알려진 사실로 초안을 작성하고, 확인 질문에는 대상 제보 ID를 붙인다. 버전이나 실패 현상의 종류가 불명확하면 임의로 구체화하지 않는다.
- 아래 네 항목 안에서 공통 설명과 제보별 차이를 표현한다. 서로 다른 문제라 별도 초안이 필요하면 나눌 수 있다. 모든 제보 ID가 결과에 남았는지, 각 문장에 붙인 모든 출처가 그 문장을 실제로 뒷받침하는지 입력과 대조한다.

## 제목 작성

- 입력에 명시된 대상과 증상만으로 핵심 문제가 드러나는 짧은 제목 한 줄을 쓴다. 원인이나 입력에 없는 정보를 덧붙이지 않으며, 기존 사실 보존 규칙을 제목에도 적용한다.
- 증상이 모호하거나 없으면 제목에 `상세 증상 미확인`을 명시한다. 예: `앱이 안 돼요` → `앱 — 상세 증상 미확인`.
- 대상이 없으면 임의로 붙이지 않는다. 대상과 상세 증상이 모두 없으면 `대상·상세 증상 미확인`으로 쓴다.

## 출력 형식

이슈 제목: 한 줄 제목

### 증상

관찰된 문제와 입력에 명시된 발생 조건·빈도·오류 메시지.

### 재현 순서

입력에 명시된 재현 행동과 순서.

### 기대 동작

제보자가 명시한 정상 동작.

### 확인이 필요한 정보

누락되거나 모호한 내용을 확인하는 질문 목록.
