# Issue Summary

제공된 버그 제보를 한 줄의 이슈 제목과 아래 네 항목으로 간결하게 정리한다.

## 정리 원칙

- 입력에 있는 사실만 사용한다. 원인, 환경·버전, 재현 단계, 기대 동작을 추측하거나 외부 지식으로 채우지 않는다.
- 제보자의 추정은 추정으로 표시한다. 불확실한 표현, 발생 빈도, 오류 메시지를 보존하고 모순된 내용은 임의로 확정하지 않는다.
- 재현 순서는 입력에 명시된 행동과 순서만 번호 목록으로 적는다. 순서가 불명확하면 알려진 행동만 나열하고 순서 확인이 필요하다고 표시한다. 누락된 준비 단계나 중간 행동을 추가하지 않는다.
- 증상·재현 순서·기대 동작 중 제공되지 않은 항목은 `입력에 없음`으로 표시한다. 정보가 부족해도 우선 정리 결과를 제공한다.
- 빠지거나 모호한 정보 중 이슈를 이해하고 재현하는 데 필요한 내용만 마지막 항목에서 짧은 질문으로 묻는다. 이미 제공된 정보를 다시 묻지 않는다. 필요한 질문이 없으면 `없음`으로 표시한다.

## 제목 작성

- 입력에 명시된 대상과 증상만으로 핵심 문제가 드러나는 짧은 제목 한 줄을 쓴다. 원인이나 입력에 없는 정보를 덧붙이지 않으며, 기존 사실 보존 규칙을 제목에도 적용한다.
- 증상이 모호하거나 없으면 제목에 `상세 증상 미확인`을 명시한다. 예: `앱이 안 돼요` → `앱 — 상세 증상 미확인`.
- 대상이 없으면 임의로 붙이지 않는다. 대상과 상세 증상이 모두 없으면 `대상·상세 증상 미확인`으로 쓴다.

## 출력 형식

이슈 제목: 한 줄 제목

### 증상

관찰된 문제와 입력에 명시된 발생 조건·빈도·오류 메시지.

### 재현 순서

입력에 명시된 재현 행동과 순서.

### 기대 동작

제보자가 명시한 정상 동작.

### 확인이 필요한 정보

누락되거나 모호한 내용을 확인하는 질문 목록.
