# 프로젝트 작업 지침

이 프로젝트는 결제 서비스와 연결되지 않은 환불 계산 예제다. 현재 요청과 `README.md`의 해당 요구를 읽고 작업한다. README에 후속 요구가 있어도 아직 요청하지 않은 기능을 먼저 구현하지 않는다.

## 작업과 검사

- 요구의 입력·반환값·오류 조건에 맞추어 변경하고, 기존 두 인자 호출의 호환성을 유지한다.
- `data/`의 기대 결과는 업무 요구를 설명한다. 현재 구현의 출력에 맞추어 기대값을 약화하거나 실패한 검사를 삭제하지 않는다. 요구와 자료가 충돌하면 근거를 알린다.
- 요구를 바꾸는 코드에는 정상 입력과 관련 경계·오류 사례의 검사를 추가한다. 현재 요구에 해당하지 않는 후속 기능의 검사를 미리 추가하지 않는다.
- 작업 후 프로젝트 폴더에서 전체 기능 검사를 실행한다. Windows PowerShell은 `python -X utf8 -B -m unittest discover -s tests -v`, macOS·Linux·WSL은 `python3 -X utf8 -B -m unittest discover -s tests -v`를 사용한다. 실행 가능한 기능의 실제 출력도 해당 요구의 실행 명령으로 확인한다.
- 명령 실행이 실패하면 실행 위치·파일·인터프리터 문제인지, 프로그램의 실제값과 기대값이 다른 문제인지 먼저 구분한다. 수정 뒤 같은 검사를 다시 실행하고 결과를 확인한다.
- 원인을 해결하지 못한 채 같은 명령을 반복하지 않는다. 막힌 원인, 확인한 근거, 진행에 필요한 정보를 보고한다. 실행하지 못한 검사는 통과로 보고하지 않는다.

## 완료 보고

변경한 동작, 실제 실행한 명령과 결과, 남은 문제를 짧게 보고한다. 테스트 통과와 실제 Hook 연결 확인은 서로 다른 결과로 구분한다.
