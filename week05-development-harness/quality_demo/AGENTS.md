# 프로젝트 작업 지침

이 프로젝트는 결제 서비스와 연결되지 않은 환불 계산 예제다. 현재 요청과 `README.md`의 해당 요구를 읽고 작업한다. 후속 요구는 해당 활동을 시작할 때 구현한다.

## 설명과 작업

- 학습의 중심은 입력 계약, 책임 분리, 검사와 피드백, 결과 완전성이다. 특정 언어의 문법·타입 특성을 핵심 개념이나 이해의 완료 기준으로 삼지 않는다. 언어별 구현 설명은 실제 코드·실행을 이해하는 데 필요한 보충으로 둔다.
- 입력 형식은 외부 입력 경계에서 검증하고, 계산 코드는 검증된 금액과 면제 여부를 받아 업무 규칙을 적용한다. 기존 두 인자 호출의 계산을 유지한다.
- `data/` 기대값은 업무 요구에 근거한다. 현재 출력에 맞춰 기대값을 낮추거나 실패한 검사를 삭제하지 않는다.
- 현재 요구의 정상·경계·오류 사례를 기존 검사와 함께 확인한다. 이후 Day의 미구현 기능을 현재 요구의 실패로 보고하지 않는다.

## 실행과 실패 대응

- IDE의 Gradle 검사 또는 프로젝트 폴더의 `gradlew.bat test`(Windows PowerShell: `.\gradlew.bat test`), `./gradlew test`(macOS·Linux·WSL)로 전체 업무 검사를 실행한다. 기능의 실제 출력도 README의 명령으로 확인한다.
- Hook 코드 검사는 별도 `hookTest` 작업이다. `prepareHook`로 의존성을 준비한 뒤 Hook 이벤트는 `PostToolUseReview.java`를 직접 실행한다. Hook 안에서 Gradle을 다시 호출하거나 업무 코드를 컴파일하지 않는다.
- 실패하면 실행 위치·JDK·의존성·명령 문제와 업무 기대값 불일치를 출력으로 구분한다. 원인을 고친 뒤 같은 검사를 실행한다.
- 새 근거 없이 같은 실패를 반복하지 않는다. 해결하지 못하면 원인과 필요한 정보를 보고하며, 실행하지 못한 검사를 통과로 보고하지 않는다.
- 배치의 결과 완전성을 다룰 때는 입력·결과 식별자와 순서, 누락, 성공·오류 내용까지 업무 계약과 대조한다. 종료 코드 0만으로 완료하지 않는다.

## 배치 완료 전에 실행할 검사

- 배치를 실행할 때 이번 표준 출력을 UTF-8 파일로 저장하고 배치 종료 코드도 확인한다. 표준 오류는 별도로 보관한다. 실행이 실패했다면 과거 출력이나 기대 파일을 이번 실행 결과로 대신 사용하지 않는다. 실행 예시는 README의 「이번 출력 검사와 완료 판단」을 따른다.
- 완료 보고 전에 이번 입력·업무 기대 결과·저장한 실제 출력에 `checkBatch`를 실행한다. 제공 자료의 Windows 명령은 `.\gradlew.bat -q checkBatch --args="data/batch-requests.json data/batch-expected.json .local/current-batch/actual.json"`이다. 다른 결과를 확인할 때는 세 경로를 그 검사 대상에 맞춘다.
- `checkBatch`의 출력과 종료 코드를 읽는다. 통과하면 그 파일의 요청별 대응을 확인한 근거로 사용한다. 올바른 오류 행도 처리된 결과다. 기존 업무 검사는 `.\gradlew.bat test`로 함께 확인한다.
- 검사 실패·출력 없음·판독 불가이면 해당 결과의 완료 판단을 보류하고, 메시지에 나온 누락·중복·식별자·내용 또는 파일 문제의 원인을 확인한다. 필요한 부분을 수정하거나 배치를 다시 실행한 뒤, 완료 근거로 삼을 출력 파일에 같은 검사를 실행한다. 새 배치를 실행하는 테스트의 통과만으로 기존의 잘못된 출력이 해결됐다고 보고하지 않는다.
- 비교용 복사본의 결함이면 정상 업무 코드와 기대값을 바꾸지 않는다. 반례를 거부하는 검사 기능의 성공과 그 반례 자체의 검사 실패를 구분한다. 재검사한 파일과 판정 근거를 완료 보고에 연결한다.
- 판정은 검사 명령의 출력으로 Codex에 전달하고 이 지침에 따라 다음 행동을 정한다. Hook을 이 경로의 필수 조건으로 두지 않는다.

## 완료 보고

변경 동작, 실제 실행 명령·결과, 남은 문제를 짧게 보고한다. 업무 검사, Hook 코드 검사, 실제 Host 연결과 후속 행동을 구분한다.
