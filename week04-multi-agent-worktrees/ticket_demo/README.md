# 작업을 둘로 나누어 보는 티켓 표시 예제

이미 실행되는 Java 코드입니다. 생성된 `week04-multi-agent-worktrees/ticket_demo/`을 IDE에서 엽니다. JDK 17 이상으로 Gradle 프로젝트를 엽니다. Wrapper가 빌드 도구와 JUnit을 준비하므로 Gradle을 따로 설치하지 않습니다. 최초 실행에는 다운로드가 필요합니다. Day별 학습과 위임 요청은 [주차 README](../README.md)에 있습니다.

Windows PowerShell:

```powershell
.\gradlew.bat -q run
.\gradlew.bat test
```

macOS·Linux·WSL:

```bash
./gradlew -q run
./gradlew test
```

현재 완료 구현의 출력은 `[긴급] 로그인 오류`입니다. 최초 제공본은 `[P0] 로그인   오류`였고, 아래 두 변경과 후속 요구를 완료했습니다.

기본 두 변경은 다음과 같습니다. 주차 Day 1에서 선택한 추가 조건은 이 README에 함께 적고, 각 작업이 맡을 범위와 처리 순서를 Day 2에서 정합니다.

- 제목 작업: `Titles.java`에서 앞뒤 공백과 연속 공백·탭·줄바꿈을 한 칸으로 정리합니다. `src/test/java/lab/week04/TitlesTest.java`에 대표 사례를 추가합니다. 반환값은 문자열입니다.
- 우선순위 작업: `Priorities.java`에 `P0 → 긴급`을 추가합니다. `src/test/java/lab/week04/PrioritiesTest.java`에 새 값과 기존 P1·알 수 없는 값 사례를 추가합니다. 반환값은 문자열입니다.
- 통합 작업: 두 변경을 합친 뒤 기존 테스트와 새 테스트를 실행하고 `App.java`가 정확히 `[긴급] 로그인 오류`를 출력하는지 확인합니다.

위 분할은 시작 예시입니다. 주차의 추가 요구가 두 함수나 공통 조립부에 영향을 주면, 먼저 역할·반환 약속·작업 순서를 선택하고 이 README의 담당 범위도 갱신합니다. 개별 Worktree는 합의한 범위만 수정합니다. 공통부를 별도 통합 담당에게 맡기거나 선행 변경 후 다른 작업을 진행할 수 있으며, 서로 의존하는 변경을 무조건 병렬로 수행하지 않습니다. Day 4에는 선택한 방식으로 변경을 합쳐 개별 검사와 통합 결과를 확인합니다.

`src/main/java/lab/week04/`의 `App.java`는 두 함수의 결과를 조립하고 `Titles.java`·`Priorities.java`는 표시할 문자열을 반환합니다. `src/test/java/lab/week04/`는 기존 동작과 변경 요구를 확인합니다. 위임·통합 근거와 판단은 `../two-changes.md`에 이어 씁니다.

실습의 설명은 정보 의존·책임 분리·반환 계약·통합 확인이라는 원리를 중심으로 읽습니다. 메서드 표기와 빌드 명령은 이 원리를 실행하는 구현 예입니다.

## 현재 완료한 요구

공백뿐인 제목은 `(제목 없음)`으로 표시합니다. 원래 제목이 공백뿐이고 P0이면 `App.renderTicket`이 `[긴급] 담당자 확인 필요`를 반환합니다. P1·P2·P3·미등록 값에는 일반 대체 제목을 사용하며, 실제 입력이 `(제목 없음)`인 P0는 그 제목을 유지합니다.

두 입력을 함께 판단하는 조건은 조립부가 맡고, 제목 정리와 우선순위 이름 매핑은 각 구성에서 재사용합니다. 현재 전체 JUnit 검사는 16개입니다. 위임·통합에서 확인한 판단은 `../two-changes.md`에 연결했습니다.
