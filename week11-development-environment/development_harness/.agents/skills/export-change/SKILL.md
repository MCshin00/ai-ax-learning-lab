# 문의 내보내기 변경

이 Skill은 요구를 현재 코드의 책임과 검사 가능한 결과로 연결한다. 공통 작업 원칙과 검사 실행 기준은 `AGENTS.md`를 따르고, 현재 파일 역할과 실행 위치는 `docs/project.md`에서 확인한다. 요구별 입력·기대 결과·판단 이유는 `data/acceptance-cases.json`에서 가져온다. 이 Skill에 사례의 기대값이나 현재 클래스 배치를 고정하지 않는다.

## 사례 선택

1. 요구 ID가 주어지면 해당 ID의 사례를 조회한다. 자연어 요청이면 요구 목록의 ID와 `requirement`를 살펴 가장 직접적인 사례를 고른 뒤 상세 사례를 조회한다. 예를 들어 “큰따옴표도 보존해 줘”는 `CSV-QUOTE`의 제목 조건에 해당한다.
2. 선택한 사례의 `input`, 기대 결과 필드, `decision`을 함께 읽는다. 기대 결과 필드는 요구마다 다르므로 `expectedCell`만 있다고 가정하지 않는다. 후보가 여럿이거나 기존 사례로 판단할 수 없는 요청은 차이를 밝히고 필요한 요구 조건을 확인한다. 새로운 요구라면 입력·기대 결과·판단 이유를 사례에 추가할 근거를 마련한다.
3. 개발 MCP의 `get_acceptance_case(id)`가 연결되어 있으면 상세 조회에 사용한다. 자연어와 ID를 연결할 때 `list_acceptance_cases`가 제공되면 그 목록을 사용한다. 도구가 아직 없거나 사용할 수 없으면 같은 JSON을 직접 읽는다. 조회 결과가 없으면 ID 선택을 다시 확인하고, 자료 읽기 오류면 연결 또는 자료 상태를 확인한다.

## 변경 위치와 검사 입력 결정

1. `docs/project.md`의 처리 경로를 현재 코드와 대조한다. `TicketExport.csv`에서 선택·셀 표현·CSV 조합으로 이어지는 호출과 공개 입력·결과를 따라가며, 사례가 요구하는 상태 변화가 어느 책임에 속하는지 판단한다. 클래스 이름만 보고 변경 위치를 결정하지 않는다.
2. 사례의 원문 입력과 기대 결과를 현재 처리에 대입해 차이를 설명한다. `CSV-QUOTE`의 `VPN, "접속"`을 다룰 때는 `CsvCell.encode`에서 셀 전체를 감싸는 조건과 내부 큰따옴표의 처리 방법을 현재 코드로 확인하고, 조회한 기대 셀과 비교한다. 이미 요구를 만족하는 부분은 기존 구현으로 검사하고, 차이가 있는 책임만 변경 후보로 삼는다. `TEAM`이라면 문의 선택과 `TicketExport`의 입력 전달을, `FILENAME`이라면 파일 이름의 입력과 호출부를 확인한다.
3. 새 조건을 구별하는 입력과 관련 기존 조건을 함께 업무 검사에 반영한다. `CSV-QUOTE`에서는 사례의 제목과 기대 셀을 사용해 완성된 CSV를 검사하고, `CSV-COMMA`의 쉼표 제목과 단순 제목도 확인한다. `DEDUP`처럼 처리 순서와 반환 정보가 결과를 바꾸는 요구는 기대 ID·개수와 호출부까지 연결한다. 사례에 없는 결과를 임의로 기대값으로 만들지 않는다.

## 결과 확인

변경 후 `AGENTS.md`의 기준대로 업무 검사를 실행하고, 실패하면 사례의 입력·기대값·실제값을 대조해 수정한다. 변경한 동작은 `docs/project.md`에 반영한다. 사례의 입력·기대 결과는 구현의 올바름을 판단하는 기준이므로 업무 요구가 달라진 근거가 있을 때만 갱신한다. 결과를 전할 때 사용한 요구 ID 또는 자연어 조건, 바뀐 책임과 검사 입력, 실제로 확인한 동작을 연결한다. 자동 검사 결과와 코딩 도구에서 Skill·MCP가 실제로 선택·호출된 사실은 구분한다.

## 개발 MCP에 필요한 조회 정보

`get_acceptance_case(id)`는 정확한 요구 ID를 받아 원래 사례의 `id`, `day`, `requirement`, `input`, 해당 요구의 기대 결과 필드, `decision`을 반환해야 한다. `list_acceptance_cases`가 있다면 자연어 요청의 후보 선택에 필요한 `id`, `day`, `requirement`만 반환하면 된다. 없는 ID와 자료 읽기·파싱 실패는 구별되어야 한다. MCP 구현과 연결 전에는 로컬 JSON이 같은 판단 자료이다.
