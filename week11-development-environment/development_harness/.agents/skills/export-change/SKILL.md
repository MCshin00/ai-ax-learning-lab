# 문의 내보내기 변경

## 요구와 현재 처리 확인

1. `AGENTS.md`에서 작업 원칙을, `docs/project.md`에서 현재 기능과 검사 위치를 읽고 관련 코드와 대조한다.
2. 요청에서 확정된 조건과 결과를 바꿀 미정 조건을 구분한다. 기존 대화·문서에 결정이 있으면 사용한다. 선택이 필요하면 실제 입력에서 결과가 어떻게 달라지는지 보여 주고 처리 방식을 추천한 뒤 의견을 반영한다.
3. 입력부터 출력까지 호출을 따라가며 요구와 현재 동작의 차이를 찾는다. 바꿀 처리를 선택하고 공개 입력·반환값에 영향을 받는 호출부와 검사도 확인한다.

## 검사 입력과 구현

1. 업무 요구와 선택한 처리 규칙에서 작은 입력과 기대 결과를 도출한다. 예를 들어 큰따옴표가 있는 제목은 원문과 CSV 셀 표현 규칙으로 기대값을 정한다. 중복 처리라면 같은 ID의 상태가 다른 입력으로 처리 순서의 영향을 확인한다.
2. 새 조건을 구별하는 입력과 변경의 영향을 받는 기존 입력을 검사에 담는다. 현재 구현이 돌려주는 값과 기대값이 다르면 요구·규칙·구현을 대조해 원인을 판단한다.
3. 선택한 위치를 구현하고 호출부·관련 검사·프로젝트 설명을 함께 갱신한다. 같은 설계 안의 단순 수정은 정해진 조건에 따라 진행한다.

## 분담과 통합

1. 조건이 합의되면 메인이 현재 작업 공간의 변경과 사용할 Worktree를 확인한다. 파일·호출부·검사 소유권이 겹치지 않는 변경만 동시에 맡긴다. 분담이 이득이 없는 작은 변경은 한 담당이 처리한다. 이번 요청의 담당 수와 배정은 `docs/project.md` 또는 `.local/harness/checkpoint.md`에서 확인하고, 다음 요청에 고정값으로 적용하지 않는다.
2. 담당에게 선택한 업무 규칙, 구별할 입력과 기대 결과, 담당 파일, 검사 대상과 결과 위치, 이미 시도한 실패 수정과 남은 연결의 보고 방법을 전달한다. 서브에이전트가 시작 Hook의 문맥을 자동으로 받았다고 가정하지 않는다. 메인은 담당 완료를 기다리고 변경 파일과 검사 근거를 확인한다. 공유 호출부는 담당별 결과가 확인된 다음 통합 담당에게 전달한다.
3. 담당별 검사는 각 변경의 입력과 결과를 확인한다. 통합 뒤에는 메인이 같은 작업 공간에서 두 변경을 함께 쓰는 입력의 `acceptance`와 대표 실제 출력을 확인한다. 검사 결과가 없거나 다른 작업 공간의 결과라면 완료로 보지 않는다. 확인한 결과와 남은 연결을 `.local/harness/checkpoint.md`에 갱신해 다음 단계에 전달한다.

## 실행과 결과 해석

`AGENTS.md`의 기준으로 검사를 실행한다. 메인이 실패한 입력·기대값·실제값을 읽고 해당 담당에게 같은 실패의 집중 수정을 한 번 요청한 뒤 재검사한다. 담당의 기존 수정 시도도 한 번에 포함한다. Stop Hook은 최종 판정만 하며 별도 수정 요청을 하지 않는다. 같은 실패가 남거나 환경 조치 뒤에도 실행할 수 없거나 업무 선택을 바꿔야 하면 결과 위치와 이유를 남기고 중단한다.

결과에는 요청한 조건, 바뀐 처리, 대표 입력과 실제 출력을 연결한다. 예상과 달랐던 이유와 추가로 확인할 동작이 있으면 해당 근거와 함께 설명한다. `docs/project.md`에는 확정한 업무 조건과 현재 코드·검사 위치를 반영한다.
