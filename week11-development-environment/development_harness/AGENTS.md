# 개발 지침

- 현재 기능과 파일 역할은 `docs/project.md`에서 확인한다. 현재 요청과 코드를 대조해 확정된 조건과 결정할 조건을 구분하고, 입력·기대 결과를 정해 검사에 반영한다.
- 반복할 작업 원칙은 이 파일에, 확정한 업무 조건·현재 구조·검사 위치는 `docs/project.md`에, 확인할 입력과 기대 결과는 검사 코드에 둔다. 기능 변경으로 설명이 달라지면 해당 자료도 갱신한다.
- 공개 메서드의 입력이나 결과가 바뀌면 호출부와 관련 업무 검사를 함께 확인하고 수정한다. 현재 클래스 배치를 고정하지 않고 요구에 맞춰 책임과 연결을 검토한다.
- 업무 기능을 변경하면 해당 요구의 입력을 검사에 반영하고 Gradle `acceptance`로 확인한다. 하네스 구현이나 공통 빌드 설정도 바뀌면 `test`로 전체 검사를 실행한다. IDE의 Gradle 실행으로 충분하면 그 경로를 사용한다.
- 검사 실패는 입력·기대값·실제값을 대조해 수정한다. 빌드나 검사 실행이 불가능하면 환경·설정 원인과 필요한 조치를 알린다. 검사가 없거나 실행되지 않은 상태를 통과로 판단하지 않는다.
- 확인한 동작과 아직 검사에 포함되지 않은 요구를 구분한다. 자동 검사 통과를 실제 코딩 도구의 Skill 사용·Hook 연결 확인으로 대신하지 않는다.
- 작업을 넘길 때 변경 파일·확인한 동작·남은 결정과 다음 행동을 `.local/harness/checkpoint.md`에 남긴다. 재개 시 인계 내용을 현재 코드와 검사 결과에 대조한다.
