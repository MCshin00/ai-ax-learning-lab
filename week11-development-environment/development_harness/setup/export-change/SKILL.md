docs/project.md에서 현재 입력부터 출력까지의 경로를 읽는다.
개발 MCP의 get_acceptance_case로 해당 요구의 사례를 가져온다. 연결되지 않았다면 data/acceptance-cases.json의 같은 사례를 읽는다.
조회한 입력·기대 결과에서 현재 출력과 다른 조건을 찾고, 어느 처리와 검사를 바꿀지 이유와 함께 추천한다. 새 구조나 처리 순서를 정할 때 학습자의 의견을 반영한다.
원문과 업무 조건으로 기대 결과를 정해 lab/export 패키지의 업무 검사에 반영한다. 이미 처리하는 조건은 기존 구현으로 확인하고, 남은 조건을 구현한다.
결과 형태가 달라지면 사용하는 호출부와 검사를 함께 맞춘다. 작업을 나눌 때는 구현 파일과 검사 파일의 담당도 나눈다.
acceptance 결과와 diff에서 조회한 조건이 반영된 위치, 실제 입력·결과와 남은 판단을 연결해 설명한다.
