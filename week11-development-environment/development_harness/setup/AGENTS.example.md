# 개발 지침

업무와 파일 역할은 docs/project.md를 먼저 확인한다. 현재 요청의 제공 사례를 data/acceptance-cases.json에서 찾아 입력과 기대 결과로 설계 이유를 설명한다.
공개 메서드의 입력이나 결과가 바뀌면 호출부와 acceptance 검사를 함께 변경한다.
검사 실패는 실제 입력·기대·결과를 비교해 고친다. 실행 환경 문제는 소스 수정으로 해결하지 않고 필요한 조치를 알린다.
작업을 넘길 때 변경 파일, 확인한 동작, 남은 결정을 .local/harness/checkpoint.md에 짧게 남긴다.
