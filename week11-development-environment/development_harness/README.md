# 개발 하네스 실습 자료

상세 학습은 [주차 본문](../README.md)의 Day 1~5를 따릅니다. Java 17 이상에서 IDE의 Gradle 동기화 후 `test`를 실행합니다. 제공 기능은 단순한 OPEN 문의 CSV 내보내기이며, 변경할 업무 요청과 개념 해설은 주차 본문의 각 Day에 있습니다.

`src/main/java/lab/export`가 개발할 업무 코드입니다. `acceptance`는 `lab/export` 패키지의 업무 검사를, `test`는 프로젝트의 모든 검사를 실행합니다. 지침·Skill·Hook·검사 연결·재개 방법은 업무 요구에서 필요한 역할을 정해 AI와 만듭니다.

Day 1은 지침을 만들어 쉼표 처리에 사용하고, Day 2는 반복할 개발 절차를 Skill로 만들어 자연어 큰따옴표 처리 요청에 사용합니다. Day 3은 검사 실행·판정·피드백을 구현해 줄바꿈 실패가 수정으로 이어지는지 확인합니다. Day 4는 시작 시 정보 전달을 구현하고 팀 선택·파일 이름 변경을 분담·재개해 통합합니다. Day 5는 중복 처리 요구로 전체 환경을 사용하고 조정합니다.

| 파일 | 사용하는 이유 |
|---|---|
| `docs/project.md` | 세션 시작과 재개에 필요한 기능·코드·검사 위치 |
| `src/main/java/lab/export/ExportExample.java` | CSV를 IDE에서 확인할 진입점 |
| `src/test/java/lab/export/ExportAcceptanceTest.java` | 초기 업무 동작의 검사 |
| `build.gradle` | 앱 실행과 검사에 필요한 의존성·작업 |

실행 진입점과 연결 설정은 만든 구조에 맞춥니다. 상세 설계·구현·확인은 주차 본문 Day 2~4에 있습니다. `.codex/`와 `.local/`은 Git 공개 대상에서 제외합니다. Worktree를 사용할 때는 도구·검사·인계 자료가 해당 작업 폴더를 가리키게 연결합니다.

자동 검사는 확인한 사례의 동작을 판단합니다. 하네스의 판단부는 대역으로 검사하고, 실제 코딩 도구에서의 자료 조회·수정·재개는 개발 세션에서 확인합니다. 설계 선택과 실제 결과를 주차 노트에 연결합니다.
