# 0004 — 밖으로 나가는 형태는 선언하고, 변환은 한 곳에 두고, 검사로 고정한다

- 정한 날: 2026-10-08

## 상황

도구의 응답과 이후의 HTTP 응답은 다른 프로그램이 읽는다. 안에서 쓰는 값을 변환 없이 그대로 내보내면 안의 이름이 곧 밖의 형태가 되어, 안에서 이름을 바꾸는 것만으로 읽는 쪽이 깨진다.

## 결정

- 응답의 형식을 오류의 모양과 원인 값의 목록까지 선언한다. 결과 구분마다 반드시 있는 필드를 적는다.
- 해당하지 않는 필드는 보내지 않는다. `null`을 값으로 쓰지 않는다.
- 사람이 읽는 문장(`message`)과 코드가 분기하는 값(`code`)을 나눈다. 읽는 코드는 문장으로 분기하지 않는다.
- 밖으로 나가는 형태와 안에서 쓰는 값 사이의 변환은 표면(MCP 응답, HTTP 응답)마다 한 곳에 둔다.
- 표면마다 결과 구분별 대표 응답 하나를 검사에서 비교한다.

## 이유

읽는 쪽이 코드이면 응답의 형식을 알아야 하고, 그 형식을 제공하는 것은 보내는 쪽의 일이다([0011](0011-each-app-owns-its-own-responsibility.md)). 밖의 형태가 바뀔 때 고칠 곳은 최소여야 한다. 대표 응답의 비교는 필드의 이름이 바뀌거나 필드가 더해지는 변경을 의도한 것인지 확인하게 한다. 지금은 응답 전체를 문자열로 비교하는데, 필드의 순서까지 고정되는 것은 이 방식의 부수 효과이고 요구는 아니다.

필드를 빼는 것과 `null`로 보내는 것을 섞으면 읽는 쪽이 두 경우를 모두 다뤄야 한다. 잘못된 입력처럼 값 자체가 없을 수 있는 경우에도 "없으면 보내지 않는다" 하나로 설명된다.

## 다시 볼 조건

공개하는 형태가 하나뿐이고 읽는 쪽이 같은 코드 안에만 있으면 검사만으로 충분하다.
