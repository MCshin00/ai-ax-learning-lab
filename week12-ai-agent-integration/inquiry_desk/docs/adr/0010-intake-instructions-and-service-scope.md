# 0010 — 접수 지침의 예와 서비스로 적는 범위

- 정한 날: 2026-10-10

## 상황

접수를 실제 모델(gpt-5.4-mini)로 실행하자 대역 모델로는 볼 수 없던 차이가 나왔다.

| 입력 | 나온 것 | 기대 |
|---|---|---|
| `급여 시스템이 안 돼요` (세 번) | 서비스 없음, 질문 | `급여 시스템`을 적고 조회 |
| `VPN이랑 급여 시스템이 안 돼요` | 서비스 `VPN`만, "급여 시스템"은 증상에 들어감 | `VPN`, `급여 시스템` |
| `VPN이 자꾸 끊겨요` → `VPN이 아니라 통합 로그인 문제예요` | 서비스 `통합 로그인`, 증상 `문제예요` | 서비스 `SSO`, 증상 유지 |
| `통합 로그인이 느려요`, `메일이 안 열려요` | `SSO`, `MAIL` | 같음 |
| `사내망 연결이 자꾸 끊겨요`, `인터넷이 안 돼요` | 서비스 없음, 질문 | 같음 |

표에 없는 서비스가 접수 결과에서 빠졌다. 서비스가 있는지는 상태 조회가 판단한다는 결정([0008](0008-intake-result-and-service-existence.md))과 반대 방향의 결과다. 모델이 대응표를 허용 목록처럼 읽었을 가능성이 있다. 이름을 ID로 바꾸는 일은 첫 발언에서는 됐고, 이전 결과를 바로잡는 발언에서는 되지 않았다. 지침에는 규칙만 있고 예가 없었으며, 표는 어느 쪽이 이름이고 어느 쪽이 ID인지 표시하지 않았다.

## 결정

| 정할 것 | 결정 |
|---|---|
| 서비스로 적는 범위 | 직원이 이름을 말한 사내 서비스와 업무 시스템은 표에 없어도 그대로 적는다. 와이파이·네트워크·PC처럼 일반적인 환경을 가리키는 말은 서비스로 적지 않는다 |
| 대응표 | 이름에서 ID로 가는 방향을 적는다. 한 ID에 이름을 여럿 둘 수 있고, SSO에 `통합인증`을 더한다. 질문 문장에는 ID마다 첫 이름만 쓴다 |
| 지침의 예 | 모델이 받는 입력과 같은 형식으로 예를 둔다. 표에 없는 서비스, 표의 이름과 섞인 경우, 서비스가 없는 경우, 바로잡는 발언, 오류 코드를 덧붙이는 발언이다 |
| 예에 쓰는 발언 | 실제 모델로 확인할 때 쓰는 발언과 겹치지 않게 한다 |
| 표기를 맞추는 쪽 | 그대로 모델이다. 코드는 접수 결과의 서비스 이름을 바꾸지 않는다 |

## 이유

"표에 없어도 적는다"만 강조하면 `사내망`이나 `인터넷`도 서비스로 적혀 질문 대신 `NOT_FOUND`가 나갈 수 있다. 직원이 대상을 알리지 않은 문의에는 질문이 맞으므로([0009](0009-conversation-state-and-missing-target.md)) 두 경우를 가르는 문장을 지침에 둔다. 이 경계는 문장을 이해해야 가를 수 있어 모델이 맡는다.

규칙만으로 지켜지지 않은 동작은 예로 보여 준다. 다만 확인할 발언을 예에 그대로 넣으면, 다시 실행해 맞게 나와도 지침이 다른 표현에도 통한다는 근거가 되지 못한다. 그래서 예에는 `그룹웨어`, `전자결재`, `와이파이`를 쓰고 `급여 시스템`, `사내망`, `인터넷`과 제공 자료의 정정 사례는 확인용으로 남긴다.

SSO(Single Sign-On)를 우리말로 통합인증이라고도 부르므로 `통합인증`을 SSO의 이름으로 받는다. 제공 자료에는 없는 이름이다.

지침을 고치는 것으로 먼저 해결하는 것은 표기를 맞추는 일을 모델에 맡긴 결정을 유지하기 위해서다. 모델의 해석은 대역으로 확인할 수 없으므로 검사를 더하지 않고, 같은 입력을 실제 모델로 다시 실행해 확인한다.

## 다시 볼 조건

- 지침을 고친 뒤에도 표의 이름이 ID로 바뀌지 않는 경우가 남으면, 접수 결과의 서비스가 표의 이름과 정확히 같을 때 코드가 ID로 바꾸는 방식을 검토한다.
- 바로잡는 발언에서 앞의 값이 계속 사라지면 [0009](0009-conversation-state-and-missing-target.md)의 다시 볼 조건을 따른다.
- 일반적인 환경을 가리키는 말이 서비스로 적히는 일이 잦으면 경계를 지침의 예로 더 보여 준다.
- 모델을 바꾸면 같은 입력으로 다시 확인한다.
