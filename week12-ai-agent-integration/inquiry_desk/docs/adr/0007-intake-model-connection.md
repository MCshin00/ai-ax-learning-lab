# 0007 — 접수의 모델은 제공자 SDK로 직접 호출하고 형식은 제공자가 강제한다

- 정한 날: 2026-10-09

## 상황

접수는 이 앱에서 모델을 처음 호출하는 자리다. 필요한 것은 호출 한 번과, 그 응답을 앱이 다음 처리를 고를 수 있는 값으로 받는 것이다. 제공자의 SDK로 직접 호출할 수 있고, 프레임워크에 요청 조립·타입 변환·도구 호출의 반복·대화 메모리를 맡길 수도 있다.

## 결정

OpenAI Java SDK로 직접 호출한다. 응답 형식은 JSON Schema를 엄격하게 지정해 제공자가 강제하게 한다. 모델의 응답이 약속과 다르면 다시 호출하지 않고 원인 값이 있는 실패로 돌려준다. SDK의 자동 재시도도 끈다.

| 원인 값 | 언제 |
|---|---|
| `MODEL_UNAVAILABLE` | 모델을 호출하지 못함(연결, 인증, 사용 한도, 시간 초과) |
| `INVALID_OUTPUT` | 응답이 약속과 다름(완료되지 않은 응답, 거절, 형식이 다름) |

엄격한 스키마는 모든 필드를 필수로 요구하므로, 없을 수 있는 값은 모델과 주고받을 때만 `null`로 받는다. 앱이 밖으로 내보낼 때는 [0004](0004-declared-response-shape.md)대로 필드를 뺀다.

## 이유

프레임워크가 맡아 주는 네 가지 가운데 도구 호출의 반복은 쓸 일이 없다. 상태 조회는 코드가 호출하고([0001](0001-processing-roles.md)) 접수의 모델에는 도구를 주지 않는다. 대화 메모리는 메시지 목록을 다시 보내는 구조여서 이전 접수 결과만 보내는 방식([0009](0009-conversation-state-and-missing-target.md))과 맞지 않는다.

남는 요청 조립과 타입 변환은 직접 쓰는 편이 결정을 지키기 쉽다. 형식의 강제가 코드에 드러나고, 호출 실패와 형식 불일치를 SDK의 오류와 응답 상태에서 바로 나눌 수 있다.

다시 호출을 넣으면 횟수·대기 시간·비용의 정책이 따라오는데, 형식을 강제한 상태에서 약속과 다른 응답은 거절이나 잘린 출력처럼 같은 입력을 다시 보내도 같을 가능성이 높다.

## 다시 볼 조건

- 운영 문서 검색을 모델이 도구로 요청하게 정하면 도구 호출의 반복이 필요하다. 그때 직접 쓸지 프레임워크에 맡길지 다시 본다.
- 실제 모델 실행에서 형식 실패가 간헐적으로 나오면 한 번 다시 호출하는 것을 검토한다.
- 제공자를 자주 바꿔야 하면 제공자와 무관한 인터페이스를 주는 프레임워크가 맞다.
