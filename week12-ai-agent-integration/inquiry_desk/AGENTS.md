# 개발 지침

이 프로젝트의 구현 작업자가 따르는 원칙이다. 설계·작업 지시·최종 검사는 메인이 `CLAUDE.md`에 따라 진행한다. 저장소 루트의 `AGENTS.md`(환경변수 파일, 공유 자료의 경로와 민감정보, 커밋 형식)도 함께 적용된다.

## 작업 원칙

- 현재 구조는 `docs/project.md`, 정해진 결정과 이유는 `docs/adr/`에서 확인한다. 승인된 계획과 코드를 대조한 뒤 구현한다.
- 같은 입력의 결과·오류·저장 내용을 바꾸는 조건이 계획에 없으면 스스로 정하지 않고 멈춘다. 계획과 코드가 어긋나거나 계획에 없는 라이브러리가 필요할 때도 멈춘다. 멈출 때는 갈리는 입력과 선택지별 결과를 돌려준다.
- 다른 프로그램이 읽는 형태도 공개 입력·결과다. MCP 도구의 이름·설명·입력 형식·응답 형식, HTTP 요청과 응답, 실행 진입점의 인수와 출력이 해당한다. 계획에 없이 바꾸지 않고, 계획에 따라 바꿀 때는 호출부와 검사를 함께 고친다.
- 클래스와 패키지의 배치처럼 계획이 맡긴 것은 요구에 맞게 정한다. 맡아서 정한 것과 이유를 풀 리퀘스트 본문 초안에 적는다. 기존 배치를 바꿨으면 그 이유도 적는다.
- 계획의 입력별 기대 결과를 검사로 옮기고 Gradle 검사를 직접 실행한다. 고친 곳에 따라 실행할 검사가 다르다.

  | 고친 곳 | 실행할 검사 |
  |---|---|
  | 업무 코드와 그 검사(`src/main`, `src/test`) | `test` |
  | 작업자 실행 관리, Hook, 그 검사(`src/harness`, `src/harnessTest`) | `harnessTest` |
  | 둘에 함께 걸리는 것(`build.gradle` 등 빌드 설정) | 둘 다 |

- 검사가 실패하면 코드를 고친다. 계획에서 온 검사의 기대값을 바꾸거나 그 검사를 지우거나 건너뛰지 않는다. 고치는 횟수에는 제한이 없고 실행의 제한 시간 안에서 한다. 기대 결과를 바꿔야만 통과한다고 판단되면 멈춘다.
- 검사를 실행하지 못했으면 원인과 필요한 조치를 알린다. 검사가 없거나 실행되지 않은 상태를 통과로 쓰지 않는다.
- 확인한 범위를 구별해 알린다. 준비한 모델 응답으로 확인한 것과 실제 모델로 확인한 것, 서버 프로세스를 실제로 띄운 연결로 확인한 것과 값만으로 확인한 것을 나눈다.

## 끝내는 방법

마지막 응답은 요청문이 지정한 형식의 결과다. 형식은 `src/harness/resources/worker-result.schema.json`에 있다. 끝남과 멈춤은 남기는 것이 다르다.

| | 끝남(`status: done`) | 멈춤(`status: stopped`) |
|---|---|---|
| 언제 | 계획의 기대 결과를 구현했고 검사를 실행함 | 스스로 정하면 안 되는 조건을 만남 |
| 결과에 담을 것 | 요약, 변경 파일, 실행한 검사와 결과, 확인하지 못한 것, 풀 리퀘스트 본문 초안 | 요약, 질문(갈리는 입력과 선택지별 결과) 하나 이상. 그때까지 바꾼 파일이 있으면 변경 파일 |
| `docs/project.md` | 코드와 같은 변경 안에서 현재 구조로 갱신 | 고치지 않음 |
| 풀 리퀘스트 본문 초안 | 무엇을 왜 바꿨나, 맡아서 정한 것과 이유, 어떻게 확인했나, 확인하지 못한 것 | 빈 문자열 |
| 검사 | 위 표의 검사를 실행하고 기록 | 실행하지 않아도 됨 |

응답을 끝내려 할 때 종료 Hook이 `test`를 다시 실행한다. 실패하면 같은 세션에서 한 번 고치게 하고, 그 뒤에도 실패하면 세션을 멈춘다. 마지막 응답이 위 형식의 멈춤 결과이고 질문이 하나 이상이면 Hook은 검사하지 않는다. 글로만 질문을 쓰거나 결과를 다른 글로 감싸면 멈춤으로 읽지 못해 검사가 실행된다.

## 이 앱의 조건

이유와 세부는 `docs/adr/`에 있다.

- 문의를 처리하는 경로에서는 저장하지 않는다. 저장은 담당자의 확인 동작 뒤에만 한다.
- 조회 결과와 근거는 서비스별로 따로 보관한다. 한 서비스의 "없음"이나 실패가 다른 서비스의 결과를 지우지 않는다.
- 반드시 수행해야 하는 조회와 저장의 순서는 코드가 정한다. 모델에는 저장 기능을 주지 않는다.
- 도구의 결과에서 자료에 없는 것은 정상 응답 안의 "없음"으로, 하지 못한 것은 원인 값과 함께 오류로 돌려준다.
- 밖으로 나가는 형태는 오류의 모양까지 선언한다. 안에서 쓰는 값과의 변환은 표면마다 한 곳에 두고, 대표 응답을 글자 그대로 비교하는 검사로 고정한다.
- 응답을 읽는 쪽은 모르는 필드를 무시한다. 있어야 할 필드가 없으면 잘못된 응답으로, 모르는 원인 값은 받은 값을 보존한 원인 불명의 실패로, 모르는 결과 구분은 해석할 수 없는 응답으로 처리한다.

## 작업 범위

- 참고 구현 `../references/incident_desk`는 읽지 않는다.
- 환경변수 파일(`.env` 계열)과 키가 든 실행 설정은 읽지 않는다. 실제 키가 필요한 실행은 학습자가 IDE에서 한다. 검사에는 가짜 설정과 준비한 모델 응답을 쓴다.
