# 개발 지침

- 현재 기능과 파일 역할은 `docs/project.md`에서 확인한다. 요청과 코드를 대조해 확정된 조건과 결정할 조건을 구분하고 입력·기대 결과를 검사에 반영한다.
- 반복할 작업 원칙은 이 파일에, 확정한 업무 조건·현재 구조·검사 위치는 `docs/project.md`에, 확인할 입력과 기대 결과는 검사 코드에 둔다. 기능 변경으로 설명이 달라지면 해당 자료도 갱신한다.
- 공개 입력이나 결과가 바뀌면 호출부와 관련 검사를 함께 확인하고 수정한다. 현재 클래스 배치를 고정하지 않고 요구에 맞춰 책임과 연결을 검토한다.
- 업무 기능 변경은 Gradle `test`로 확인한다. Hook 변경은 `harnessTest`, 공통 빌드 설정 변경은 두 작업을 실행한다. 앱의 `test`에는 Hook 검사가 포함되지 않는다. IDE의 Gradle 실행으로 충분하면 그 경로를 사용한다.
- 검사 실패는 입력·기대값·실제값을 대조해 원인과 결과 위치를 메인에 돌려준다. 작업자가 실패 수정 요청을 스스로 반복하지 않는다. 실행 불가 시 환경·설정 원인과 필요한 조치를 알리고, 검사가 없거나 실행되지 않은 상태를 통과로 판단하지 않는다.
- 확인한 동작과 검사에 포함되지 않은 요구를 구분한다. 자동 검사 통과를 실제 Codex의 Skill 사용·Hook 발동 확인으로 대신하지 않는다.
- 작업을 넘길 때 변경 파일·확인한 동작·남은 결정과 다음 행동을 `.local/harness/checkpoint.md`에 남긴다. 재개 시 현재 코드와 검사 결과를 대조한다. 요구 합의·수정 요청·최종 확인은 메인이 `CLAUDE.md`에 따라 진행한다.

## 문의 처리 조건

- 문의를 처리하는 경로에서는 저장하지 않는다. 저장은 담당자의 확인 동작 뒤에만 한다.
- 서비스별 사실과 근거를 섞지 않는다.
- 자료에 없는 서비스는 조회 기능이 정상 응답 안의 “없음”으로 돌려준다. 조회 자체를 못 한 경우는 호출한 쪽이 원인을 구별할 수 있는 값과 함께 오류로 알린다.
- 반드시 수행해야 하는 상태 조회와 저장 조건은 코드가 관리한다. 모델에는 저장 기능을 주지 않는다.

## 작업 범위와 자료

- 참고 구현 `../incident_desk`는 읽지 않는다. 구현 후 비교는 메인이 한다.
- `.env`, `.env.*`, `*.env`, `*.env.*` 및 키가 저장된 비공유 실행 설정은 직접 또는 프로그램을 통해 간접으로 읽지 않는다. 실제 키를 읽는 앱과 실제 API 호출은 학습자가 IDE에서 실행한다. 자동 검사에는 가짜 설정·인증 입력과 파일 로더 대역을 사용한다.
- Git 공유 자료에는 민감정보와 로컬 절대경로를 넣지 않는다. 저장소 기준 상대경로나 환경변수·자리표시자를 사용한다. 로컬 실행 기록과 Windows Hook 절대경로는 Git에서 제외된 `.local/`, `.codex/`에만 둔다.
