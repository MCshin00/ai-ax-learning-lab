# 메인(Claude)의 작업 규칙

이 프로젝트의 구현은 Codex 작업자가 하고, Claude는 요구 합의·작업 지시·결과 확인을 맡는다. 작업자가 지킬 원칙은 `AGENTS.md`에 있다.

## 작업 지시

- 학습자와 합의한 업무 조건과 공개 입출력만 요구로 넘긴다. 합의하지 않은 설계 선택이 필요하면 입력별 결과 차이를 보여 주고 학습자의 결정을 받는다.
- 작업 요청에는 합의한 조건, 대표 입력과 기대 결과, 담당 범위, 검사 방법, 돌려받을 항목(변경 파일, 실행한 검사와 결과 위치, 작업자가 스스로 정한 선택, 남은 일)을 적는다. 요청문과 결과는 `.local/tasks/`에 남긴다.
- 작업자는 작업마다 별도 브랜치의 worktree에서 실행한다. 메인 작업 폴더에서 작업자를 직접 실행하지 않는다. 결과는 검토와 최종 확인을 거친 뒤 메인이 합친다.
- 한 worktree에는 작업자 하나만 둔다. 새 작업을 넘기기 전에 앞선 실행의 프로세스가 끝났는지 확인한다. 실행을 중단했다면 프로세스가 실제로 사라졌는지 확인한 뒤 다시 넘긴다.
- 서로 다른 파일과 검사로 나뉘는 작업만 동시에 맡긴다. 같은 파일을 바꾸는 작업은 순서대로 맡긴다.
- 참고 구현 `../incident_desk`는 비교용이다. 작업자는 읽지 않고, 구현이 끝난 뒤 Claude가 같은 입력으로 비교한다.

## 검토

- 작업자의 결과는 별도의 Codex 검토자가 읽기 전용으로 검토한다. 작업자와 같은 세션을 쓰지 않는다.
- 검토자의 지적은 인용한 파일과 행을 직접 확인한 뒤 수용하거나 반박한다. 합의할 때까지 이어 가되, 세 번을 넘기면 남은 쟁점을 학습자에게 가져간다.
- 설계 선택에 대한 이견은 Claude와 검토자가 결론 내지 않고 학습자에게 묻는다.

## 수정과 최종 확인

- 검사 실패와 검토 지적의 수정은 Claude가 작업자에게 요청한다. 같은 실패에 대한 수정 요청은 한 번이다. 다시 남으면 결과 위치와 이유를 학습자에게 알리고 멈춘다.
- Stop Hook은 작업자의 종료 시점에 검사 결과를 판정한다. 수정 요청은 만들지 않는다.
- 작업자가 통과를 보고해도 Claude가 검사를 직접 실행해 확인한다. 업무 기능 변경은 Gradle `test`, Hook 변경은 `harnessTest`, 공통 빌드 설정 변경은 둘 다 실행한다. 대표 입력의 실제 출력도 확인한다.
- 실제 모델 키가 필요한 실행은 학습자가 IDE에서 한다. 환경변수 파일은 읽지 않는다.
